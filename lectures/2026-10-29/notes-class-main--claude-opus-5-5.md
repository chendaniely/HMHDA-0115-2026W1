## Summary

This office-hours session introduced data visualization in R with the `ggplot2` package, using a real clinical dataset. The data was `blood_storage` from the `medicaldata` R package. It records biochemical cancer recurrence in patients who had a radical prostatectomy. The instructor followed the visualization chapter of his online textbook (ds4biomed.tech). He linked the code back to last week's topic of tidy data: every plot points to named columns, so the data has to be tidy before you can plot it.

The core idea was the **grammar of graphics**, which builds a plot in layers:

- a **data** layer,
- an **aesthetic mapping** that says which column goes where (x, y, colour, and so on),
- a **geometry** that says what to draw (bars, histograms, box plots, points).

The instructor built a bar chart one layer at a time. First came an empty grey square, then labelled axes, then bars. He then showed that the same chart can be written in several ways, including from pre-counted data with `stat = "identity"`. Each of these steps corresponds to a drag-and-drop choice in Looker Studio.

The main practical lesson was a decision process for choosing a plot:

1. Count how many variables you are looking at.
2. Decide whether each one is continuous, discrete, or categorical. A categorical variable can be nominal, ordinal or binary.

This led to histograms, box plots, violin plots, jittered points, scatter plots, colour mappings, and facets. Twice, a variable stored as a number (`TVol`, `sGS`) was really a category, and the plot came out wrong or misleading until the variable was converted with `as.factor()`. Looking at the data this way also raised analytical points: the outcome groups are unbalanced, and family history appeared related to recurrence.

### 3. The grammar of graphics and `ggplot2`

- **`ggplot2`**: The R plotting package. The "gg" stands for **Grammar of Graphics**.
  - Hadley Wickham wrote it, although the grammar-of-graphics idea did not originate with him.
  - It can describe essentially any visualization. The instructor said it is the main reason he stayed with R, even though Python is also popular for data work.
- **Layers**: A plot is built in stacked layers: data, aesthetics, geometries, facets, coordinates and theme. This session covered everything except coordinates and theme.
- **Data layer**: `ggplot(data = blood)` alone draws an empty grey square, because R knows the data but not which columns to use or what to draw.
- **Aesthetic mapping (`aes()`)**: Tells `ggplot` which column goes on which part of the plot.
  - `aes(x = Recurrence)` adds an axis covering 0 to 1, the range of that column, but still draws nothing.
  - Because you point to a column by name, the data has to be tidy. The same tidy data is also what you need later to fit models.
- **Geometry layer (`geom_*`)**: What to draw. It is added with `+`, and every geometry function starts with `geom_`.
  - `geom_bar()` draws bars.
  - Given raw data, `geom_bar()` counts the rows for each value itself. Here the bars reached just over 250 and just over 50, matching the frequency table of 262 and 54.
- **Flipping a bar chart**: Mapping the variable to `y` instead of `x` makes the bars horizontal.
- **Pre-counted data and `stat = "identity"`**: If you already have a table of counts (here `recurrence_freq`, with columns `Recurrence` and `count`), map `y = count` and use `geom_bar(stat = "identity")`. This tells `ggplot` to use your numbers as they are instead of counting.
  - Without `stat = "identity"`, `ggplot` would count rows. Each value appears once in the summary table, so you would get two bars of height 1. Copilot pointed this out when asked to explain the code.
- **Where you specify data and mappings is flexible**:
  - Data and `aes()` can go in the base `ggplot()` call, inside a `geom_*()` call, or be split between them. All give the same plot.
  - This matters because it lets you **overlay** several geometries that share the same data and mapping, or even layer **different datasets** on top of each other.
  - Example: a baseline histogram with a highlighted subset histogram drawn on top. The instructor showed this using a Python port of ggplot with a `bill_length` column.
  - Most of the time, you will put the data and mapping in the base layer.
- **Why the vocabulary matters**:
  - Every tool names the same chart differently: `geom_bar` in ggplot2, "bar" or "bar chart" in Looker Studio, something bar-related in Excel.
  - Terms such as "aesthetic mapping", "bar graph", "overlay with a different dataset", "facet" and "overplotting" are the keywords that get you good answers from an AI assistant.

### 4. Types of variables

- **Numeric, continuous**: Can take decimal values. Age is usually treated as continuous, even when recorded in whole years.
- **Numeric, discrete**: Comes only in steps. There is no half a person, and nobody has one and a half children.
- **Categorical**: Groups. R and statistics call these **factors**, because much of R's vocabulary comes from statisticians.
  - **Nominal**: Categories with no natural order, e.g. which sport you play. Running is not "more" than swimming.
  - **Ordinal**: Categories with an order, e.g. Likert scales ("how happy are you?") or **disease stages** 1 to 4.
  - **Binary**: A special categorical variable with exactly two values (yes/no, 0/1). Many statistical methods are easiest with binary outcomes. Logistic regression, which models binary outcomes, is usually the first model taught.
- **Numbers that are really categories**: A variable can be stored as a number but represent groups. In this dataset, `TVol` and `sGS` are examples. Another is the number of cylinders in R's Motor Trend cars dataset: there is no 4.5-cylinder car.
  - Convert these with `as.factor()` so `ggplot` treats them as categories. This is a very common step.
- **Turning categories into binary variables**: A common first exploratory step.
  - Example: turtle / snail / butterfly becomes "turtle" vs "not turtle".
  - Example: disease stages become stage 0 vs everything else, stage 4 vs everything else, or high vs low stage.
  - **Trade-off:** this makes the statistics simpler, but **you lose information**. The analysis can support weaker claims, or it answers a slightly different question. The instructor still does this when first exploring different cuts of the data.

### 5. Choosing a plot: one variable

- **Start by asking two things**: how many variables you want to look at, and what type each one is.
- **One categorical or discrete variable**: Bar chart, `geom_bar()`.
- **One continuous variable**: Histogram, `geom_histogram()`.
  - `geom_bar()` on age would count each distinct age. That works, but a histogram groups values into ranges (e.g. 40–45, 46–50, 51–55), which is usually more useful.
  - The bins can be adjusted. In class, `bins = 10` was used to set the number of bins.

### 6. Choosing a plot: two variables

- **Every combination has a typical plot**: continuous + continuous, categorical + continuous, categorical + categorical. Three or four variables at once can take some creativity.
- **One categorical and one continuous variable**: Box plot, `geom_boxplot()`.
  - Box plot parts:
    - the line in the middle is the **median**;
    - the box spans the 25th to 75th percentiles (the **interquartile range**, IQR);
    - points drawn individually lie beyond an IQR-based cut-off and flag possible **outliers**.
  - **Common mistake:** plotting `TVol` as it is stored gave a wrong-looking box plot, because R treated a 1/2/3 code as a continuous number. Using `as.factor(TVol)` produced one box each for 1, 2, 3 and `NA`, showing the age distribution in each group.
  - A clinical analogue: disease stage on the x-axis with age or survival on the y-axis.
- **Violin plot (`geom_violin()`)**: Shows the shape of the distribution, mirrored on both sides, so you can see where most of the data sits. A box plot hides that shape.
  - Box plots are more traditional and appear far more often in papers. Violin plots are still useful for understanding your own data. Not every plot you make is meant for publication.
- **Overlaying geometries**: A violin with a box plot on top, or a violin with points on top, are layers that share the same data and mapping. The instructor admitted the violin-plus-box version does not look great. Overlaying like this is harder in many other tools.
- **Overplotting and `geom_jitter()`**:
  - `geom_point()` stacks identical values exactly on top of each other. Many 65-year-olds look like one dot.
  - `geom_jitter()` moves each point a random amount sideways within its group. That is acceptable because the axis is categorical: there is no value of 2.3 for `TVol`.
  - The jittered points also show how few observations a group has. The `NA` group had only about six points, so its violin shape should be read with caution.
  - The jitter is random, so points move each time you run the code. There are ways to make it reproducible.
- **Two continuous variables**: Scatter plot, `geom_point()`. Example: `PVol` against `PreopPSA`.

### 7. Adding more variables: colour, shape, facets

- **More aesthetic mappings**: Besides `x` and `y`, you can map columns to `color`, `fill`, `shape` and `size`.
- **Common mistake (a misleading legend):**
  - Mapping `color = sGS` with `sGS` stored as a number produced a smooth gradient legend. That suggests values such as 1.5 or 2.75 exist.
  - In fact `sGS` only takes step values (1, 2, 3, 4).
  - `color = as.factor(sGS)` gives separate colours with no in-between values.
  - **Even the legend can change how someone interprets your data if the variable type is wrong.**
- **Colour and shape together**: It can be hard to tell a blue circle from a green star from a green circle. The instructor suggested mapping shape and colour to the **same** variable to emphasise one difference, though this is not a fixed rule.
- **Facets (small multiples)**: Split one plot into several panels by a categorical variable.
  - `facet_wrap(~ RBC.Age.Group)` splits by one variable.
  - `facet_grid(RBC.Age.Group ~ Recurrence)` splits by two variables, one along each direction of the grid.
  - Facets are a one-line addition. Once you know the word "facet", you can also ask an AI for it.
- **What the faceted plot suggested**: With colour mapped to `FamHx` (red = family history present), red points clustered in the `Recurrence = 1` panels. Family history seemed related to recurrence, even though there were few cases.
  - This is exploration, not a conclusion. Most data will not separate this cleanly.

### 8. Overplotting at larger scale, and publication plots

- **Bigger points**: Making points bigger in a busy plot eventually makes overplotting worse.
- **Hexbin plot**: Divides the scatter-plot area into hexagonal bins and shows the **count** in each bin, like a histogram in two dimensions or a heat map of the points. "Overplotting" is the term to search for, or to give an AI when asking for techniques.
- **Summary plots**: Sometimes you plot summaries instead, such as means or medians with confidence intervals using bars and lines. `ggplot2` can do this.
- **Publication conventions**: Journals tend to use traditional, familiar plots. An unfamiliar plot needs a lot of explanation of how to read it.

## Code from class

### Loading the data and counting outcomes

```r
install.packages("medicaldata")       # once only, if library(medicaldata) says "not found"

library(medicaldata)
library(tidyverse)                    # loads ggplot2, dplyr, etc.

blood <- medicaldata::blood_storage   # take blood_storage from the medicaldata package, store it as `blood`
head(blood)                           # look at the first 6 rows

recurrence_freq <- blood |>
  group_by(Recurrence) |>             # one group per value of Recurrence (0 and 1)
  summarize(count = n())              # n() counts rows in each group
recurrence_freq                       # 262 with no recurrence, 54 with recurrence
```

The instructor mentioned that the `count()` function gives the same frequency table more directly.

### Building a bar chart layer by layer

```r
# data layer only: an empty grey square
ggplot(data = blood)

# add an aesthetic mapping: axis for Recurrence appears, nothing drawn yet
ggplot(data = blood, mapping = aes(x = Recurrence))

# add a geometry layer: geom_bar counts the rows for each value
ggplot(data = blood, mapping = aes(x = Recurrence)) + geom_bar()
```

### Same chart from pre-counted data, with layers moved around

```r
# everything in the base layer; stat = "identity" means "use my counts, don't count again"
ggplot(data = recurrence_freq, mapping = aes(x = Recurrence, y = count)) +
  geom_bar(stat = "identity")

# move the aesthetic mapping into the geom layer
ggplot(data = recurrence_freq) +
  geom_bar(mapping = aes(x = Recurrence, y = count), stat = "identity")

# move the data into the geom layer too: empty base, everything in geom_bar()
ggplot() +
  geom_bar(data = recurrence_freq, mapping = aes(x = Recurrence, y = count), stat = "identity")
```

All three produce the same plot. The point is that data and mappings can sit in different layers, which is what makes overlays possible.

### One variable: histograms

```r
ggplot(blood, aes(x = Age)) + geom_histogram()

ggplot(blood, aes(x = Age)) + geom_histogram(bins = 10)   # choose the number of bins
```

`data =` and `mapping =` can be left out once you know the order of the arguments.

### Two variables: box plots, violins and jitter

```r
# does NOT show TVol properly: TVol is a 1/2/3 code but R treats it as continuous
ggplot(blood) + geom_boxplot(aes(x = TVol, y = Age))

# one box per value of TVol, treated as a category (factor)
ggplot(blood) + geom_boxplot(aes(x = as.factor(TVol), y = Age))

# violin with a box plot drawn on top
ggplot(blood) +
  geom_violin(aes(x = as.factor(TVol), y = Age)) +
  geom_boxplot(aes(x = as.factor(TVol), y = Age))

# violin with points on top: identical ages overplot
ggplot(blood) +
  geom_violin(aes(x = as.factor(TVol), y = Age)) +
  geom_point(aes(x = as.factor(TVol), y = Age))

# violin with jittered points: points shifted randomly sideways
ggplot(blood) +
  geom_violin(aes(x = as.factor(TVol), y = Age)) +
  geom_jitter(aes(x = as.factor(TVol), y = Age))

# same plot, with the shared mapping moved into the base layer
ggplot(blood, aes(x = as.factor(TVol), y = Age)) +
  geom_violin() +
  geom_jitter()
```

The last version is the tidiest way to write an overlay. Both geometries inherit the data and mapping from the base `ggplot()` call.

### Scatter plots and colour

```r
ggplot(blood) +
  geom_point(aes(x = PVol, y = PreopPSA))                         # two continuous variables

ggplot(blood) +
  geom_point(aes(x = PVol, y = PreopPSA, color = sGS))            # misleading continuous colour legend

ggplot(blood) +
  geom_point(aes(x = PVol, y = PreopPSA, color = as.factor(sGS))) # separate colour per sGS group
```

### Facets

```r
# facet_wrap: split into panels by one variable
ggplot(blood) +
  geom_point(aes(x = PVol, y = PreopPSA, color = as.factor(sGS))) +
  facet_wrap(~ RBC.Age.Group)

# facet_grid: panels by two variables, colour by family history
ggplot(blood) +
  geom_point(aes(x = PVol, y = PreopPSA, color = as.factor(FamHx))) +
  facet_grid(RBC.Age.Group ~ Recurrence)
```
